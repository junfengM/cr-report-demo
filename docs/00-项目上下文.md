## 一、项目目标

做一个**统一监管报送系统（监管报送一体化平台）的前端 Demo**，用于功能演示与方案沟通。

- **输入素材**：第三方产品说明文档（184 张功能截图 + 全部功能描述；该文档**不在本仓库**）。
- **参考边界**：**只参考附件文档中"图片所承载的功能逻辑"（字段、操作、流程、状态流转），不照抄界面视觉与交互形态。** 界面用 Element Plus 组件重新表达。
- **不含**：后端服务、数据库、真实接口。
- **数据形态**：业务样例数据、用户、角色、机构、菜单/权限**全部为代码中的 mock 数据**；前台所有增删改查操作结果**持久化在浏览器本地**（localStorage / sessionStorage）。

## 三、架构方案（无后端）

### 3.1 请求拦截层（核心技术决策）

脚手架所有页面统一经由 `src/config/axios/index.ts` → `service`（`src/config/axios/service.ts`）发起请求，URL 约定 `/admin-api/**`。

方案：**自研 axios adapter 作为 mock 引擎**，在 `VITE_MOCK_ENABLE=true` 时替换 `service.defaults.adapter`，在内存 + localStorage 中完成路由匹配、数据读写、分页、错误码包装。

```
现有页面 (views/**)  →  api/**（原样不动）  →  axios service  →  [Mock Adapter]  →  localStorage
```

优点：
1. **零新增 npm 依赖**，符合"非必要不引入新组件"。
2. `src/api/**` 下全部接口定义文件**一行不改**，页面层完全复用脚手架写法。
3. 统一返回 `{ code: 0, data, msg }`，与真实后端一致；将来接真后端只需关掉开关。

### 3.2 本地数据层

- `src/mock/db/` — 按业务域拆分的初始样例数据（种子数据，写在代码里）。
- `src/mock/store.ts` — 通用"表"仓储：`list(query)` / `page(query)` / `get(id)` / `create` / `update` / `delete`，自动持久化到 localStorage（带种子版本号，版本升级时重置）。
- `src/mock/router.ts` — URL 规则表（method + path 正则 → handler）。
- `src/mock/handlers/` — 按模块分组的路由处理器，与 `src/api/**` 目录结构一一对应。

### 3.3 登录与权限链路（保持脚手架原生链路）

脚手架链路：`login` → `get-permission-info`（返回 `user / roles / permissions / menus`）→ `wsCache` 存 `ROLE_ROUTERS` → `permission.generateRoutes()` 动态挂载路由。

Mock 只需接管：
- `POST /system/auth/login`、`/system/auth/logout`、`GET /system/auth/get-permission-info`
- `GET /system/dict-data/list-all-simple`（字典 store 依赖）
- `system` / `infra` 各 CRUD 接口

这样**切换角色登录即可演示完全不同的菜单与数据范围**。

新增统计查询时只要在 `crStat.ts` 的 `STAT_DEFS` 里声明 `filters: ['asOf']`，页面自动长出控件，不用改页面。

#### 公式SQL定制（`/cr-message/sql-custom`，组件 `CrMessageSqlCustom`）

`cr.sqlFormula`（6 条种子）+ `/cr/message-formula` CRUD/导出 + `POST /cr/message-formula/try-run`。
列表页除 CRUD 外有「试运行」：表单里的 **SQL 草稿没保存也能试**，接口 `tryRunFormula()` 做 7 项**静态解析**
（非空 / 只读关键字黑白名单 / 必须有 SELECT 与 FROM / 括号配平 / `:` 与 `${}` 占位参数 / 引用表对照 `metaTableTable` 的物理表名 /
未知表点名），逐项返回「通过 / 提示 / 不通过」与结论，**不执行 SQL、不改任何数据**（该接口进 `e2e:auth` 的 `COMPUTE` 清单，
用整库行数快照证明不落库）。字段与校验规则都是**按通行做法提案**的 —— 需求文档该章只有一句「用于定义 SQL」。

### 过程中发现并修复的坑（供后续页面参考）

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| `check-permissions.mjs` 把 3 个已授权的按钮标识报成"缺失" | 扫描 `BUTTONS` 的正则只匹配两元素元组，而本轮给部分按钮加了第三个元素（`ADMIN_ONLY`，用于"页面开放、按钮只给管理员"） | 正则放宽为「第二项 + 可选的第三项（数组字面量或标识符）」，并补跑门禁确认 231/231 |
| 附件页 `v-hasPermi` 写成常量（`PERMS.upload`）被判为未授权 | `check-permissions.mjs` 的正则是**只认字符串字面量**的静态扫描，不做符号解析 | `v-hasPermi` 一律写字符串字面量；常量只在 TS 侧用 |
| CSV 错误行的行号和文件里对不上（第 8 行报成第 6 行） | 旧实现先按内容过滤掉空行再交给校验器，行号被"压实"了 | `parseImportRows()` 只在**内容为空**时跳过、空行仍占一个行号，错误提示里的行号与 Excel 里看到的一致 |
| 批次转审核的原因显示错（明明是有错误行，却提示"导入权限要求审核"） | 页面自己按 `config.needAudit` 猜原因，没考虑"有错误行也会转审核" | 原因由接口算好放进 `message`（`存在 N 行错误 / 警告` / `导入设置要求审核` / `导入权限要求审核`），页面只负责显示 |
| 「请求参数」列永远是空字符串 | 种子与 handler 调 `collectParamsOf(protocol, '', period)` 时机构代码写死成空串 | 加 `orgCodeOf(orgId)` 从 `reportOrgs()` 反查机构代码，种子与实时取数共用 |
| 填报岗能审批/回滚/删除自己导入的批次（接口层没有校验） | 只在 `BUTTONS` 里把按钮收窄成管理员，handler 没判角色 —— 知道接口地址就能绕过去 | 新增 `assertBatchAdmin()`，`audit` / `rollback` / `remove` / `/delete` / `/delete-list` 全部先判角色，提示语带上当前账号 |
| 用 `eval.mjs` 驱动页面时拿不到组件实例 | 组件实例的 `type.__name` 来自**文件名**（`ImportDialog`），`defineOptions({ name })` 只改 `type.name` | 调试脚本里按 `type.name \|\| type.__name` 匹配；生产包 `setupState` 拿不到 `<script setup>` 绑定，验证脚本要**只用 DOM 交互**才在静态产物上也能跑 |
| 合成事件打不开 `el-select` 下拉 | 监听器在 `.el-select__wrapper` 的 `click` 上，往内部 `input` 派发 `mousedown` 不生效 | 按 `mousedown` → `mouseup` → `click` 三连派发到 wrapper，之后从 `.el-select-dropdown__item` 里挑可见项点击 |
| `onPut is not defined` | `handlers/auth.ts` 用了 `onPut` 但只导入了 `onGet, onPost` | 补齐导入 |
| 空目录仍出现在侧边栏 | 目录节点 `implemented` 默认 true，被当成存活锚点 | `visibleMenuRows` 只把非目录节点（`type !== 1`）作为锚点，目录靠子节点反挂；`routeTreeForRoles` 再递归剪空目录 |
| 页面按钮全部消失（`v-hasPermi` 不生效） | `BUTTONS` 的 key 是路由 key（`cr-task/template`），`flattenMenus` 却按 `component` 路径（`cr/task/template/index`）查 | `walk` 逐级拼出 `routeKey` 再查表，`component` 查表作为兜底 |
| 直接访问 `/cr/task/template` 打不开 | 真实路由是目录 path + 子段：`/cr-task/template` | 演示与文档中一律使用 `/cr-xxx/yyy` 形式 |
| 顶级分组名不显示 | 单子节点时 Element Plus 折叠父级 | 顶级目录显式 `alwaysShow: true` |

### 自检脚本

无头 Chrome + CDP 直驱（不引入 playwright/puppeteer 依赖）：

```bash
pnpm e2e          # 链路自检（登录/菜单/列表/弹窗），10 项断言
pnpm e2e:crud     # 增删改查 + localStorage 持久化自检，5 项断言
pnpm e2e:pages    # 逐页巡检：遍历全部已下发路由，断言页面渲染且无 JS 异常
pnpm e2e:perms    # 静态检查：页面用到的 v-hasPermi 是否都在 mock 菜单里授权
```

> - 依赖本机 `~/Library/Caches/ms-playwright` 下的 chrome-headless-shell；
>   换机器用 `CHROME_BIN` 指定浏览器，用 `APP_URL` 指向其他地址。
> - `pnpm e2e:pages --filter=cr-meta` 可只巡检某个模块。
> - **`pnpm e2e:perms` 是防"按钮整块消失"的关键门禁**：`v-hasPermi` 命中未授权标识时，
>   按钮会直接从 DOM 移除且控制台不报错，只有这个静态检查能发现。

### 并行开发约定（多 agent 同时写代码时）

为了让多个方向可以同时开工而不互相踩脚，做了三件事：

1. **mock handler 自动发现**：`src/mock/index.ts` 用
   `import.meta.glob('./handlers/**/*.ts', { eager: true })` 自动加载，
   新增业务接口只需要新建 handler 文件，**不用改入口文件**。
2. **权限标识集中在 `src/mock/db/menu.ts` 的 `BUTTONS`**，能力清单先行定义，页面照抄；
   统一由一人维护，避免多人改同一文件。
3. **菜单可见性由 `implemented` 标记控制**：页面没做完就不下发该菜单，
   演示时不会点进 404。每完成一批，统一在 `menu.ts` 里把 `implemented: false` 去掉。

### 并行开发的实测教训

| 现象 | 原因 | 应对 |
| --- | --- | --- |
| 整个应用突然白屏，所有并行任务都跑不了自检 | handler 自动发现意味着**任何一个 handler 有编译错误，`import.meta.glob` 就会整包失败** | 每写完一个文件立刻 `curl` 该文件确认 200；合并前跑一次 `pnpm e2e` |
| `pnpm e2e` 结果时好时坏 | dev server 被并行写入反复热重载，页面在断言瞬间正处于 reload | 只在无人写代码时跑门禁；连续 3 次结果一致才算数 |
| 页面按钮整块消失 | `v-hasPermi` 命中未授权标识 | 能力清单（`BUTTONS`）先行，`pnpm e2e:perms` 静态拦截 |
| 字典改了但页面还显示旧码值 | 字典数据也走 localStorage 持久化 | 改种子数据后必须 `SEED_VERSION` +1（本次已升到 v2） |

4. **批处理进度靠查询推进**：`/cr-data-monitor/page` 每次轮询推进运行中任务的进度，因此页面停留时能看到进度真实增长。
   报文生成页的进度条同理，是按 50ms/条回放接口返回的日志（**结果数据是真的**，进度是演出效果）。
5. **部分枚举未入字典**：增量方式/采集方式/协议/职责等用页面内常量；「不脱敏」用哨兵值 `NONE`。
6. **导出仍是 CSV 而非 xlsx**：所有"导出"按钮落地的都是 CSV（脚手架自带的导出能力），不是 Excel 文件。
7. **工作台节点链路的报文口径带任务门槛**：`crTaskTable` 与 `crSubmitStatusTable` 是两套独立种子
   （任务域铺 6 张月报、报文域铺另一套 12 张，只有 4 张重叠），如果只按 `(机构, 报表, 期次)` join，
   会出现「报文生成 > 上级审核」的下游倒挂。因此报文/报送两个节点要求任务**已进入上级审核及以后**
   （`SUBMIT_GATE_STATUSES = [80, 90]`）。若改成只认 `status = 90`，本期末两格会变成 `1 / 0`
   （4 条已通过任务里只有 1 条在报文域有已生成记录），完成率会显示 0%，故保留 80/90 门槛。
   口径与切换方式写在 `src/mock/handlers/crDashboard.ts` 文件头。
8. **历史期次的报文数据是兜底推出来的**：202603~202607 在报文域没有种子数据，
   工作台对"整期无报文记录"的期次退回任务口径（`status = 90` 即视为已生成且已报送），趋势线才画得出来。
9. **报文文件不做压缩**：机构文件配置里上海/广东的 `compress = true`，但 Demo 不下发 zip，拿到的是未压缩明文。
10. **文件名命名规则里的占位符未展开**：`{date}` / `{tableCode}` 这类占位符在配置页可配可存，
    但实际生成文件名仍按 `HX_{机构代码}_{报表代码}_{期次}.{后缀}`。
11. **逾期数据是刻意播种的**：202608 期次有 3 条任务（上海/江苏/广东各 1）的截止日被特意设为 `2026-09-08` / `2026-09-10`，
    否则当期截止日 09-15 未到，「逾期未报」会恒为 0、演示时这张卡片没有意义。
12. **填报明细行数与报文行数是两套口径**：填报页一条记录对应报表里的一行（24~52 行），
    一键报送的报文有 860~4,800 行。两处同机构同报表同期次的报文**文件名与字节数完全一致**（共用 `crSubmitFile` 生成器），
    但不会等于填报页的行数——因为报文里还含未在前端铺开的明细。
13. **报表定制的字段来源分两类**：27 张数据表里只有 7 张（T01/T05/T06/T08/T15/T18/T27）在「列管理」中铺了完整字段，
    其余表由 `db/crMessage.ts` 的 `GENERIC_COLUMNS` 生成一组通用演示字段（机构代码 / 数据日期 / 业务主键 / 金额 …），
    保证报表定制对任意报表都能演示「选字段」；接真后端时这里应换成元数据接口。
14. **报文集生成只写「报文上报状态」**：不生成报送批次与批次明细（那是一条独立链路，见「数据报送清单」），
    生成的报文 `batchNo` 为空；如需在报送清单里看到报文集生成的报文，需再补一步批次登记。
15. **「系统直连 / 接口推送」的取数是确定性生成的，但调用链已完整留痕**：采集方式页的「立即采集」不会真的去连源系统，
    而是按 `(orgId, reportId, period)` 用 `buildCollectedRows()` 造出与机构规模相称的行数（同一组合结果稳定），
    再走真实的解析 → 校验 → 入库 / 待审核链路。新增的「连接测试」同样是确定性模拟（采集地址为空、该采集方式已停用、
    或 `id % 5 === 0` 时失败 —— `id=5` 是「上海分公司 · 团险核心系统 · 接口推送」，留着演示"测试不通"），
    但**每次测试与每次采集都会往 `cr.collectJob` 落一条记录**（任务号 `CJ+期次+4 位` / 追踪号 / 请求参数 / 耗时 / 返回行数 /
    关联批次 / 操作人），「取数记录」抽屉读的就是它；种子里的历史记录由采集方式的"上次采集结果"反推，两页口径永远一致。
    接真后端时把这两步换成真实取数接口与真实探测即可，记录结构不用改。
16. **历史导入批次只是记录，不会回放进填报数据**：种子里的 10 个批次（含已入库 / 待审核 / 解析失败 / 已驳回）
    是从 `cr.fillData` 已铺行数反推出来的展示数据，不会在启动时写库；只有页面上新做的导入才真正改 `cr.fillData`。
17. **导入文件在浏览器里解析，支持 CSV / TXT / XLSX**：`ImportDialog` 对 CSV/TXT 用 `File.arrayBuffer()` + `TextDecoder(charset)`
    按生效模板切列；对 **.xlsx 用 `xlsx.ts` 自研解 ZIP + 读 sheet XML（零依赖，`DecompressionStream('deflate-raw')`）**，
    日期单元格归一化成 `yyyy-MM-dd` 后按模板的日期格式改写，取第一张工作表。CSV 与 XLSX 共用 `parseImportRows()`
    同一套校验规则（不再各写一套）。**旧版 .xls（BIFF）不支持**，会提示另存为 .xlsx/CSV；ZIP64、加密工作簿、
    多工作表选择、单元格数字格式套用都未支持。单批最多入库 300 行（演示环境防止 localStorage 写爆）且不超过账号权限上限；
    错误行与警告行由前端按「必填 / 数值 / 日期格式 / 批次内保单号重复」四条规则判定，后端做业务判定（期次可写、导入权限、能否覆盖、是否需审核）。
18. **补录「执行补录」只打开通道**：把该「机构 × 报表 × 期次」的填报记录置为未填报并给出数据填报页深链，
    不会自动清空或重建数据；真正的补录数据仍要机构在填报页录入或重新导入。
19. **脱敏执行只覆盖填报明细里的三个字段**：字段配置可以配任意数据项，但真正能改写的是 `cr.fillData` 上的
    `holderName`（DE102 投保人名称）/ `certNo`（DE105 证件号码）/ `policyNo`（DE001 保单号）——只有这三个字段在填报数据里存在。
    「脱敏结果查询」的种子数据里还有手机号 / 邮箱 / 地址的对照行，那批是独立的展示种子，不来自执行。
20. **脱敏后可以还原，是演示特权**：真实系统脱敏不可逆（原文不落库）。Demo 为了让「执行 → 看对照 → 还原 → 再执行」能反复演示，
    把脱敏前原文留在 `cr.desensitize.originalValue` 上；「还原」= 按批次把原文写回填报数据 + 删掉本批次的对照行（批次状态置为已还原）。
21. **脱敏日志里的历史批次是种子记录**：11 条种子批次（执行成功 8 / 部分失败 1 / 执行失败 1 / 已还原 1）只用于日志展示，
    启动时不会回放进 `cr.fillData`；只有页面上新执行的批次才真正改数据。
    批次号按 `DS + 期次 + 4 位序号` 独立编号（种子与执行同一口径，取该期次已用最大序号 + 1，删掉批次也不会撞号）。
22. **字段配置的「命中条件」只落库不参与判定**，执行时按「该字段全量脱敏」处理；优先级只在同一数据项配了多条时决定用哪一条。
25. **没有任何可处理的值时，接口层会直接拒绝执行**（不再落一条「执行失败」的脏批次）：`maskedRows === 0 → 状态 4` 现在只在
    真实异常时才会出现，页面上的「重复执行」会收到一句「已跳过」的提示而不是新增一条失败记录。
23. **未执行脱敏前，填报页与填报导出里的证件号就是 18 位原文**（这是上一版「出生即掩码」改过来的后果）：
    页面上直接可见、`/cr-data/fill` 的导出 CSV 也是原文；脱敏只发生在「脱敏执行」里，演示时请把这一点讲清楚。
    真实系统里应在入库/落库环节就做可逆加密或按角色列级权限控制，不会把原文直接暴露在明细页。
24. **执行是同步完成的**：一次执行 = 一次接口调用（实测 30~70 ms 处理 52 行 × 2 字段），没有后台跑批与进度条；
    预检给的「待处理行数」就是将要改写的字段值个数，执行后可以在「数据填报」页逐行核对。
26. **导入权限是真校验，但只覆盖四项判定**：`effectiveImportAuth()` 按「用户级 > 角色级，机构+报表精确 > 指定机构 >
    指定报表 > 全部机构全部报表」取一条生效规则，落在 `/cr/collect-import/parse` 与 `/cr/collect-channel/collect` 上
    （`assertImportAuth()`，不是只藏按钮；系统管理员不受限制），判定「能不能导 / 能不能覆盖 / 要不要审核 / 单批上限」。
    **没有做机构数据范围过滤**：填报岗进「数据导入」能看到全部机构的批次（真实系统应按角色数据范围过滤列表），
    也没有按文件类型/报表做更细的授权粒度。规则未命中时**默认拒绝**（比"默认放行"安全，但会让新账号一开始导不了，需管理员授权）。
27. **补录附件存的是 base64**：Demo 没有文件服务，页面把文件读成 data URL 交给 mock 存进 `cr.supplementFile`
    （单文件 ≤ 1MB、每个申请 ≤ 3 个、同名不重复，超限给中文提示），因此「下载」拿到的是真实内容、CSV/TXT/图片能在线预览。
    真实系统里应换成文件服务（上传拿 URL、下载走签名地址）。种子里那两条附件是代码里生成的真实 CSV；
    `cr.supplement` 中另外几条只有附件名的历史记录**没有文件内容**，页面会标明「仅登记名称」，不做成假下载链接。
28. **「数据导入」页对填报岗开放**（菜单角色由「管理员专属」改为 管理员 + 填报岗）：否则导入权限永远只对超管生效、等于没做。
    页面里「审核 / 回滚 / 删除」三个按钮通过 `BUTTONS` 元组的第三个元素收窄到管理员，填报岗只保留
    查询 / 数据导入 / 批次详情 / 导出。副作用：**filler 的可见页面数从 10 变成 11**。
29. **导入页的单批行数与权限上限取小**：提交时只提交 `min(300, 权限单批上限)` 行，且批次上写的总行数 = 实际提交行数
    （不再出现"批次写 500 行、实际入库 300 行"这种对不上账的情况）；被截断时页面会先说清楚。
30. **转发审核的原因由接口返回**：批次转「待审核」可能是「有错误 / 警告行」，也可能是导入设置或导入权限要求审核；
    `parse` 的返回里带 `message` 与 `authSource`，页面直接显示，不再自己猜原因（上一版曾把"有错误行"误报成"导入权限要求审核"）。

31. **脱敏执行必须走审批（页面已无直接执行按钮）**：管理员在「脱敏执行」提交申请 → 审核岗在「脱敏审批」放行 → 那一刻才真正改写填报数据；
    申请单与执行记录是**同一条 `cr.desensTask`**（省掉主子表）。审批是**单级**的：没有会签、多级、转办，也没有消息通知
    （只在申请列表和统计卡片上有「待审核」数量）；撤回只允许申请人本人或系统管理员，且仅限「待审核」状态。
    **留痕**：`auditTrail` 逐条追加 提交 / 审核通过 / 驳回 / 执行 / 还原（谁、什么时候、意见或改写了多少值），
    审批弹窗与日志详情抽屉都用时间线显示；例外是**撤回** —— 申请单会被删掉（它没动过数据），撤回留痕只在当次提示里出现，不留库。
    `/cr/desens-execute/run` 仍在（执行内核），但页面上已无入口 —— 这是有意的，别为了演示方便接回按钮；
    它是**只允许系统管理员**调用的写接口（第三轮独立审核就是在这里发现"填报岗与匿名请求都能直接放行并改写数据"）。
    放行前会**复算**一次：申请单上的"预计脱敏 N"是提交那一刻的快照，之后有人补录/导入/还原就会过期，
    审批弹窗顶部用红条给出「申请时预计 N → 现在预计 M」，放行时把差异写进 `auditRemark` 与留痕（只提示，不阻断放行）。
32. **生效期与适用期次是两个维度**：生效期（起止日期）按「系统当天」（接口返回的 `today`）判断 未生效 / 生效中 / 已过期；
    适用期次（`periods`，可多选，空 = 全部期次）按「这次跑哪一期」判断，只在预检 / 提交申请 / 执行时生效
    （种子示例：江苏分公司 × BX011 的保单号配置只适用 202607，跑 202608 预检时它出现在「本次不参与的配置」里，
    理由写明「仅适用 202607 期次（本次 202608）」）。
    两个刻意的简化：① 日期取浏览器所在机器的当天，演示机上改系统日期会跟着变（保持"只有一处口径"）；
    ② 字段配置列表的「生效判断」列没有"这次跑哪一期"的上下文，所以对写了期次的配置只说「生效中（仅 X 期次适用）」，不判它在某一期生不生效。
    生效期只填一端时另一端显示「不限」；两端都空 = 长期有效。
33. **命中条件是本项目自定义的语法子集**：`字段 运算符 值`，多条件用 `&&`（且）/ `||`（或）连接，
    运算符只有 `= != > >= < <= 包含 不包含 为空 不为空`。**不支持括号分组、函数、字段间比较**；
    数值比较走 `Number()`，日期按字符串比大小（格式统一 `yyyy-MM-dd` 时成立）。
    条件写错（字段名不认识 / 语法不通）会**拦下整个提交**并给中文原因，不会"当全量脱"——宁可拦下也不扩大脱敏范围；
    `/cr/desens-execute/run` 遇到坏条件也先报条件错（原来先判"有没有可改写的值"，会把条件错误报成"都已脱敏或为空"）。
    **"按命中条件跳过 N 行"是并集口径**：一行只要不满足任意一个字段的条件就算被跳过（`countRowsSkippedByCondition()`，
    预检 / 申请单 / 批次 / 种子四处同源）——取各字段最大值会低估（两个字段各跳 33 行时实际是 42 行），
    页面文案因此写成「（至少一个字段不满足）」。
34. **同一「机构 × 报表 × 数据项」只有一条配置生效**（优先级数字小的，再按 id 早的），
    所以字段配置列表上有「生效判断」列显式标出 生效中 / 被同范围其它配置覆盖 / 不在生效期 / 已停用
    （种子数据里留了一条"被覆盖"的重复配置用于演示）。系统只**提示**覆盖，不会阻止你新增重复配置。
35. **数据拆分只做分组，不复制也不改写数据；但每个包都能下载成真实文件**：包文件与「一键报送」共用同一套生成器
    （`planReportFile()` / `buildSubmitFile()`），格式（TXT/CSV/XML）、分隔符、表头行数取该机构的《报送文件配置》，
    文件名 = `HX_机构码_报表码_期次_包名.后缀`（如 `HX_110000_BX011_202608_BJ-BX011-P01.txt`），
    下载到的**字节数与数据行数就是包清单上显示的那两个数字**（下载时若对不上会按真实内容回写并 `console.warn`，与报文模块同一条纪律）。
    仍然要如实讲的三点：① 包里的**明细行是按定宽规则生成的模拟数据**（与报文文件同一口径），不是把 `cr.fillData` 里的原值逐行导出；
    ② 拆分**不复制、不改写** `cr.fillData`，包内也不重新排序，行序与填报数据一致；③ 包文件**不会登记进「数据报送清单」**
    （那两张表仍按"整表 × 期次"登记），要报送整表仍走「一键生成报文」。
    其余口径：按字段值分组时单次上限 50 包（超出会提示改用「按行数均分」）；`cr.splitRule` 有**显式优先级字段**
    （数字小的先生效，缺省 50，同范围优先级相同才看后建的），停用后自动回落到下一条（没有可用规则时预检会直接说"没有启用的拆分规则"）。
    **数据拆分的详细口径是按通行做法提案的**（附件文档里只有这一节的标题与截图，工程内没有可对照的字段说明），演示时请如实讲。

36. **"接口层鉴权"严格说是"按前端携带的 userId 判角色"**：mock token 就是明文约定 `Bearer mock-token.<userId>.x`，
    `currentUser()` 从 `Authorization` 头反解 userId，**没有签名、没有过期、没有服务端会话** ——
    手工塞一个 `Bearer mock-token.1.x` 就能冒充管理员（独立审核实测跑通）。纯前端演示无解，所以：
    ① 演示与文档都**不要把它讲成安全边界**，它是"该拦的入口都拦一遍、别只藏按钮"的工程纪律；
    ② 真实系统里这层要换成服务端会话 + 角色 / 机构数据范围判定（本轮只做到"按角色"，还没有按机构数据范围过滤，
    `/cr/data-fill/save|restore` 也只要求登录）；③ 新增写接口时照 `pnpm e2e:auth` 的清单加一条，别让"漏一个 toggle"再发生。

> **为什么不用脚手架上自带的 `pnpm build:dev`**：它走 `--mode dev`，加载的是上游的 `.env.dev`
> （`VITE_BASE_URL` 指向 `api-dashboard.yudao.iocoder.cn` 等外部演示环境），这套环境不是给本 Demo 配的。
> Vite 的加载顺序是 `.env` → `.env.local` → `.env.[mode]` → `.env.[mode].local`，
> **`.env.[mode]` 会覆盖 `.env.local`**，所以 `pnpm dev`（`--mode env.local`）能用，
> `build:dev` 出来的包登录会卡在登录页（无请求、无报错、无提示，排查成本很高）。
> 结论：本 Demo 的开发与构建统一用 `env.local` 这一套环境。

> （`python -m http.server` 没有回退，深链接会 404，导致逐页巡检跑不完）。

### 交付与复制（2026-09-13 新增）

**目标**：开发机在 macOS 上，但演示要拿到**别人的 Windows 电脑**上跑，对方最好什么都不用装。

**一条命令**：`node scripts/make-release.mjs` → `release/` 下两个包（脚本本身零依赖，只用 node 内置模块）：

| 包 | 内容 | 体积 | 对方要做什么 |
| --- | --- | --- | --- |
| `cr-report-demo-win-x64.zip` | `dist/` + `node/node.exe`（Windows Node 运行时）+ `server/serve.mjs`（自定位静态服务，端口占用自动顺延）+ `start-demo.bat` + `README.txt` | 36.6 MB | 解压 → 双击 `start-demo.bat`（**零安装、不联网**） |

`node.exe` 打包时从 nodejs.org 下载并用官方 `SHASUMS256.txt` 校验 sha256（脚本内实现，含 302 跟随与进度），下载缓存留在 `release/.cache/`，重复打包不再下载。`release/` 已进 `.gitignore`。

**本轮为"可复制"修掉的六处**（都属于"在别人机器上会出问题"的隐性假设）：

| # | 问题 | 影响 | 修法 |
| --- | --- | --- | --- |
| 1 | `node_modules/` + `.pnpm-store/` 共 2.3 G，且 `.modules.yaml` 里 `storeDir` 是**本机绝对路径** | 直接拷过去 = 看起来装好了其实坏的 | 交付包一律由 `git archive` / 构建产物生成，天然不带这两样；文档里写明不要拷 |
| 2 | `.env` 里百度统计**默认开着**（`VITE_APP_BAIDU_CODE` 有值） | 每次打开页面都往 `hm.baidu.com` 发请求；给银行/保险客户演示不合规，离线时还多一次失败外联 | 留空关闭；复验：产物里 grep 不到 `baidu`、运行时 `script[src]` 探针返回 `[]` |
