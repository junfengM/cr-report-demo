# 统一监管报送平台 Demo — 演示脚本与话术

> 这份文档解决一个问题：**换个人坐到电脑前，也能把这套系统从头讲到尾。**
> 每一页给四样东西：**点什么 → 说什么 → 应该看到什么 → 异常分支怎么圆**。
> 所有数字都是在本机实测过的（不是"设计上应该"），改数据后如与本文不符，以页面为准并回来改本文。

- 配套文档：`docs/00-项目上下文.md`（事实源）、`docs/01-页面开发规范.md`（写法约定）
- 演示环境：`pnpm dev` → http://localhost:5173（**演示期间不要重启 dev server**，改文件走 HMR）
- 账号：`admin` / `filler` / `reviewer` / `auditor`，密码统一 `admin123`；数据范围演示另用真实用户 `zhoubj`（周北京）/ `wush`（吴上海），密码同上

## 一、演示前 3 分钟准备

| 步骤 | 命令 / 操作 | 目的 |
| --- | --- | --- |
| 1 | `pnpm dev`（已在跑就别动） | 确认 http://localhost:5173 能打开 |
| 2 | 浏览器硬刷新一次（Cmd+Shift+R） | 拿到最新 `SEED_VERSION` 的种子数据（改过 mock 种子后必须做） |
| 3 | 用 `admin / admin123` 登录 | 演示主线用管理员，权限主线再切账号 |
| 3b | （可选）演示动线 F 前，先去「自动采集 → 批量监控」把数据日期筛成 `2026-09-01` 看一眼 | 四种运行状态（成功 / 失败 / 等待前置 / 运行中）都在这一天，不用现场造失败 |
| 4 | 打开 DevTools → Application → Local Storage，确认 `cr-mock:table:cr.crTask` 存在 | 数据是从 localStorage 现算的，空库说明没播种 |
| 5 | 演示前**不要**点「自动提醒 → 立即执行一次」 | 那是压轴互动，点一次会生成 300+ 条提醒记录 |

**一句话开场**（建议逐字念）：

> 这是一个「统一监管报送平台」的前端演示，**没有后端**：所有接口由项目内自写的 axios mock adapter 接管，
> 数据存在浏览器 localStorage 里。所以您现在看到的每一个数字、每一次校验、每一条审批流，
> 都是真的在跑代码 —— 只是数据落在本地，刷新不丢、清缓存就回到初始种子。

## 三、动线 A：报送主链路（P0，15 分钟）

### A1. 工作台 `/index`

- **点什么**：登录后默认落地。
- **说什么**：首页是角色化的——不同账号看到的待办、统计口径不同；这一版给管理员看全局待办。
- **应该看到**：待办卡片 + 图表，数字不为 0。
- **异常分支**：如果图表空白，先看右上角有没有红色的接口报错提示（mock 抛的中文原因会以通知形式弹出）。

### A2. 报表任务管理 → 我的任务 `/cr-task/my-task`

- **点什么**：进页面 → 选「报送期次 = 202608」→ 查询 → 点某一行看详情。
- **说什么**：任务是"机构 × 报表 × 期次"的三元组，状态从待下发一路走到审核通过，**打回是可逆的**（回到填报中）。
- **应该看到**：列表按状态分色标签；详情里能看到任务流转与截止日期。
- **异常分支**：空列表 → 换期次（种子里主力期次是 202608，另有 202607 的历史数据）。

### A3. 报表数据处理 → 数据填报 `/cr-data/fill`

- **点什么**：选一条待填报任务 → 表格里改两个值 → 「保存」→ 再点「数据校验」。
- **说什么**：填报页的每一列都带校验口径；**校验是服务端算的**，不是前端正则——错误原因由接口返回。
- **应该看到**：保存后提示成功；校验后出现错误/警告行（种子里有刻意留的错值）。
- **异常分支**：想演"校验拦住你"，把某个必填项清空再校验，会看到中文错误原因。

### A4. 数据检核管理 → 数据校验 `/cr-check/validate`（含「校验结果查询」）

- **点什么**：跑一次校验 → 切到结果查询 → 按错误级别筛。
- **说什么**：校验规则是配置出来的（非空 / 长度 / 范围 / 逻辑 / 表间 / 枚举），规则维护页就是给业务自己配的。
- **应该看到**：问题清单带数据项、错误级别、机构。
- **异常分支**：如果没人配置规则，界面会提示"没有启用中的规则"，不是空白。

### A5. 数据审核 → 复核操作 / 本级审核 `/cr-audit/review`、`/cr-audit/local`

- **点什么**：勾选一条 → 「复核通过」或「打回」→ 打回时**必填原因**。
- **说什么**：打回必须给原因，原因会进"打回记录"，后面统计页会按机构统计打回次数。
- **应该看到**：批量通过后状态变化；打回记录里能看到原因。
- **异常分支**：不填原因点打回，会被接口用中文原因拦下。

### A6. 一键报送 → 报文生成下载 `/cr-submit/report-file`

- **点什么**：生成 → 下载（真的会下载到文件）。
- **说什么**：文件是按监管报文格式拼出来的**真实文本/文件**，不是假的下载链接；文件里的行数、文件名里的机构码/报表码/期次都对得上。
- **应该看到**：下载下来的文件名形如 `HX_110000_BX011_202608.txt`，打开能看到定宽报文。
- **异常分支**：如果浏览器拦了下载，检查右上角是否有多文件下载授权提示。

### A7. 一键报送 → 数据报送清单 `/cr-submit/list`

- **点什么**：按机构/期次筛 → 展开详情。
- **说什么**：这是"报了什么、报给谁、有没有回执"的总账；回执状态由报送状态表驱动。
- **应该看到**：报送状态（未报送 / 报送中 / 已报送 / 已回执）分色。
- **异常分支**：有失败态记录是**正常**的（种子里留了失败样本），正好用来讲"失败了怎么办"。

## 四、动线 B：权限与数据范围（10 分钟，本轮新增最值得讲的部分）

> 这一段的中心思想：**页面上藏按钮 ≠ 拦住人**。所以本轮把权限做到了接口层，并且能当场演示"绕过页面直接调接口"也会被拒。

### B1. 监管码值配置（5 页）→ 本地标准映射 `/cr-dict/local-map`

> 这一章现在 5 页齐（2026-09-13 补齐）：**码值字典维护** `/cr-dict/reg-dict`、**码值管理** `/cr-dict/reg-code`、
> **本地字典管理** `/cr-dict/local-dict`、**本地枚举管理** `/cr-dict/local-code`、**本地标准映射** `/cr-dict/local-map`。
> 想演「新增一个本地渠道码值」：先本地字典管理 → 本地枚举管理新增 `L99 演示渠道` → 回映射页新增映射，
> 两个下拉里立刻能选到（下拉是现读这四张表的，不是写死的常量）。删字典/删码值被引用时会被接口拦下并说明原因。

- **点什么**：进页面 → 看红黄标签 → 点「映射校验」看汇总 → 新增一条映射（本地码值 ↔ 监管码值 + 优先级）。
- **说什么**：监管下发的码值和我们系统内部的码值不是一套，**这张表就是两套码值之间的桥**。
  校验会告诉我们四类问题：**没映射、重复映射、映射指向了不存在的监管码值、映射被停用**。
  同一个本地码值配了多条时，**只有一条生效**（优先级小的、再按 id 早的），列表里有「生效判断」列写明谁盖住了谁。
- **应该看到**（种子里的四类问题各留了一个）：
  - `L06 其它` —— **未映射**（红色，报错级）；
  - `L14 港澳通行证` —— 配了两条启用映射（C04 优先级 10、C02 优先级 50）→ **重复映射（警告）**，优先级 50 那条显示"被覆盖"；
  - `L33` → `G09` —— 指向了**不存在的监管码值**（红色）；
  - `L06 → A09` —— 映射本身**已停用**（灰色，不参与生效）。
  - 汇总卡片（本机实测，2026-09-13 复测）：**本地码值 17 / 已映射 15 / 未映射 1 / 监管码值不存在 1 / 覆盖率 88.2%**；列表共 **18 条**映射（种子）。
    > 覆盖率 = 已映射 15 ÷ 本地码值 17 —— 只算**能真正取到监管码值**的映射；`L33 → G09` 指向的监管码值不存在，所以不计入分子。
  - 校验弹窗标题写的是「发现 1 个必须处理的问题（未映射 1 / 监管码值不存在 1）」，另外两条是提示级（重复映射 1 / 已停用映射 1）。
- **异常分支**：想演"存不进去"，把监管码值填成一个不存在的编码 → 接口中文报错「监管码值不存在或已停用」。

### B2. 权限审批管理 → 数据权限配置 `/cr-system/data-scope`

- **点什么**：看列表 4 条规则 → 点「生效判断」→ 填一个用户/角色看命中结果。
- **说什么**：这是"谁能看哪些机构的数据"的规则表。判定顺序是 **用户级 > 角色级**，同级再比**优先级（数字小的赢）**，最后比 id。
  种子里的看点：**周北京（用户级，优先级 20，指定机构 [11]）** 会盖住角色「报送填报岗」的"本级及以下"；
  「复核岗」配的是"全部数据"但**已停用**——停用的规则不参与判定，页面上会明说。
- **应该看到**：生效判断给出"命中第 N 条 + 中文理由"；被覆盖的规则显示原因。
- **异常分支**：如果某用户一条都没命中，会回落到**角色管理页里配的默认数据范围**（这是刻意的兜底，不是漏洞）。

### B3. 权限审批管理 → 部门权限配置 `/cr-system/dept-scope`

- **点什么**：看 6 条规则 → 点「生效判断」→ 选"上海分公司 × BX011 保费收入统计表"。
- **说什么**：数据权限管"看得到哪些机构"，部门权限管"**这个部门对这张报表能做哪些动作**"（填报 / 复核 / 审核 / 报送）。
  规则表里：总公司四个动作全给；北京/江苏/广东给"填报 + 报送"；
  **上海分公司 × BX011 只给「填报」**——所以它不能报送这张表。**没有命中任何规则 = 默认拒绝**（不是默认放行）。
- **应该看到**：动作列显示中文（由服务端返回的 `actionLabels`），生效判断里写清来源。

### B4. **接口层真拦截**（这一段是全场最有说服力的 30 秒）

- **点什么**：不切页面，直接用调试脚本**冒充填报岗**调管理接口（`--user=admin` 只是让浏览器以管理员登录着，请求头里带的是伪造的填报岗令牌）：

  ```bash
  node scripts/e2e/eval.mjs "(async () => {
    const m = (await import('/src/config/axios/index.ts')).default
    try {
      await m.put({ url: '/cr/data-scope/update', data: { id: 1 }, headers: { isToken: false, Authorization: 'Bearer mock-token.2.x' } })
      return '放行了(有问题!)'
    } catch (e) {
      await new Promise(r => setTimeout(r, 1200))
      const t = document.querySelector('.el-notification__title')
      return '被拒：' + (t ? t.innerText.trim() : '(没看到提示)')
    }
  })()" --user=admin
  ```

- **说什么**：注意这个请求**根本不经过页面**——没有按钮、没有菜单，直接打接口，照样被拒，而且拒绝原因是人话。
  （令牌里的 `2` 是**用户 id**，指填报岗张天报；换成 `.1.x` 就是管理员。）
- **本机实测输出**：`被拒：「数据权限规则修改」仅 系统管理员 可操作（当前账号：张天报）`
- **应该看到**：中文拒绝原因；同一请求换成管理员令牌就能通过。
- **异常分支**：如果看到英文报错或"系统异常"，说明 mock 抛错方式不对（必须 `throw new Error('中文')`）。
- **数字背书**：`pnpm e2e:auth` 会把 **97 条写接口**逐个用冒充身份探一遍（必须全部被中文原因拒绝），并把 6 条"看着像查询其实会落库"的接口用**整库行数快照**证明没写数据。

### B5. 机构数据范围（用真实账号演，30 秒）

- **点什么**：右上角退出 → 用 `zhoubj / admin123` 登录 → 进「数据采集 → 数据导入」。
- **说什么**：同一个页面，管理员能看到全部机构的批次；**周北京只能看到北京分公司**的。
  这不是前端过滤——列表接口自己按登录人算了可见机构（`/cr/collect-import/page` 接了数据范围）。
- **应该看到**：管理员视角 10 个批次 / 4 个机构；`zhoubj` 视角 **3 个批次、只有北京分公司**。
- **异常分支**：如果看到别的机构，先确认是不是用管理员登录着（换个浏览器 profile 更保险）。

## 五、动线 C：配置与治理（P1，15 分钟）

### C1. 报文配置（5 页）`/cr-meta/*`

- **点什么**：机构管理 → 报表管理 → 口径管理 → 字段映射 → 报送期次，按顺序点一遍。
- **说什么**：这 5 页是**报送的元数据**：谁报、报什么、每个数据项什么口径、字段对应报文哪个位置、每期什么时候开窗关窗。
  报文生成页的文件结构就是照这套元数据拼的。
- **应该看到**：期次页能看到当前期次与截止日；字段映射页能按报表筛选。
- **异常分支**：口径/字段为空不是 bug（新报表还没配），页面有中文空态。

### C2. 数据采集 → 数据导入 `/cr-collect/import`

- **点什么**：新建导入 → 选渠道（系统直连 / 文件导入 / 接口推送 / 手工录入）→ **拖入一个 CSV/XLSX** → 解析预览 → 确认入库。
- **说什么**：文件解析是**零依赖**实现的（CSV 与 XLSX 都自己解析，见 `src/views/cr/collect/import/xlsx.ts`），
  解析会逐行报错、**错误行不会被静默丢弃**；导入权限按"接口范围 + 机构 + 报表"生效判断，未命中默认拒绝。
- **应该看到**：解析预览表 + 错误行清单 + 成功率；入库后批次详情里行数对得上。
- **异常分支**：可以用一个格式不对的文件演示"解析失败批次"（种子里也有），错误原因逐行给出。

### C3. 数据脱敏 → 脱敏字段配置 / 脱敏审批 / 数据拆分 `/cr-desensitize/*`

- **点什么**：
  1. 字段配置页看「生效判断」列（生效中 / 被覆盖 / 未生效 / 已过期）；
  2. 执行页点「提交执行申请」（**只算不动**）→ 顶部红条显示"申请时的数字"；
  3. 切到 `auditor` 账号进「脱敏审批」→ 看**放行前复算** → 放行；
  4. 回来看执行结果 + 留痕时间线；
  5. 数据拆分页：预检 → 执行拆分 → 逐包**下载真实报文文件**。
- **说什么**：脱敏最危险的不是"没脱"，而是**"以为脱了其实没脱"**。所以有三道保险：
  ① 同一"机构 × 报表 × 数据项"多配置时只有一条生效，页面告诉你谁盖住了谁；
  ② 预检 / 申请单 / 执行结果**三个数字同源**，不会打架；
  ③ 放行前**复算**：数量、口径签名（换了规则/条件）、原文指纹（哪一行是什么值变了）三层比对，有差异就红条提示。
- **应该看到**：申请单状态"待审核"；审核岗放行后状态变"已执行"且字段值真的变了；留痕里逐条记录谁在什么时候做了什么。
- **异常分支**：复算是**提示不阻断**（审核岗仍可放行）——这是刻意的，演示时如实说；差异原因写在红条里。

## 六、动线 D：P2 新增（统计 / 报表 / 集成 / 服务 / 提醒，15 分钟）

### D1. 报送数据统计（13 个查询）`/cr-stat/*`

13 页共用一套渲染：**筛选栏（机构 / 报表 / 期次，个别页另有时点 / 归档月份）→ 口径说明 → 指标卡 → 图表 → 明细表 → 导出**。

| 页面 | 路径 | 一句话口径 |
| --- | --- | --- |
| 报送进度统计 | `/cr-stat/progress` | 按机构看任务下发/填报/审核到哪一步；完成率 = 已完成 ÷ 任务数 |
| 报送及时率统计 | `/cr-stat/timely` | 按时 = 提交时间 ≤ 截止日；未报单列 |
| 任务完成情况统计 | `/cr-stat/task` | 任务在各流转环节的分布 |
| 报送数据量统计 | `/cr-stat/volume` | 填报行数 vs 导入行数（两者口径不同，**不合并成一个数**） |

### D3. 系统集成（接入系统 / 接入权限 / 接入附件）`/cr-integration/*`

### D5. 自动提醒（规则 / 记录）`/cr-remind/*`

## 七、动线 F：任务调度（自动采集，10 分钟，2026-09-13 新增）

菜单在**「自动采集」**分组下（`/cr-schedule/*`）。这是需求文档里最后一个整章缺口，也是全场**最适合演"失败与依赖"**的一段：
跑批结果是确定性的，成功 / 失败 / 等待前置 / 运行中四种状态**都留了种子**，可以反复重放。

### F1. 任务维护 `/cr-schedule/task`

- **点什么**：左侧点分组「报表加工汇总」（4 个任务，2 个高优先级）→ 右侧看列表；点任一行的**「前置任务」**。
- **说什么**：任务是**按分组组织**的，同一个分组内执行顺序是「优先级 → 任务编号」；**任务编码是跑批日志的关联键，创建后不允许修改**。
  前置任务不是装饰——它决定批量监控里落「等待前置任务」还是照跑。
- **应该看到**：弹窗里能多选前置任务，并有一块**只读的「谁依赖它」**（把当前任务当前置的其它任务），所以改之前就知道会影响谁。
- **异常分支**：① 把任务自己当前置 → 中文拒绝「不能把任务自己配成前置任务」；
  ② 造成循环依赖（A→B→A）→ 中文拒绝并**点名是哪条链路流回了本任务**；
  ③ 删一个被别的任务当前置的任务 → 中文拒绝，且**列出引用它的任务编码**（还会提示它有几条调度配置要先删）。
- **诚实边界**：依赖校验是真的（自我依赖 + DFS 环检测 + 引用校验都在接口层）；但**跑批本身是模拟**的，不会真去连数据库跑存储过程。

### F2. 批量监控 `/cr-schedule/monitor`（这一段是重点）

- **点什么**：数据日期筛选填 `2026-09-01` → 查询 → 看 6 个指标卡（总记录数 / 成功 / 失败 / 等待前置 / 运行中 / 新增数据量合计）
  → 找到状态为**失败**的那行点「立即执行」→ 再点一次**运行中**那行的「立即执行」。
- **说什么**：这就是跑批的**全量流水**：数据日期、存储过程英文名/中文名、分组、执行方式（自动调度 / 手工调度）、运行状态、
  开始结束时间、执行时长、新增数据量、**SQL 执行返回值与错误信息**、操作人。指标卡的数字**全部来自接口**（不是前端自己 filter 列表算的），所以和列表永远一致。
- **应该看到**：四种状态同屏 —— 成功、失败（`ORA-01652: 无法扩展临时段…` 这类真实感错误文案）、
  **等待前置任务**（错误信息里直接点名是哪个前置任务、什么状态，不写"未知原因"）、运行中（没有结束时间与耗时）。
- **异常分支**：① 点失败行的「立即执行」→ 重跑**成功**（同一个任务 + 同一个期次结果稳定，换期次才会变），并提示新增行数与耗时；
  ② 点运行中那行 → 中文拒绝「该任务正在运行中，不能重复触发」；③ 点「前置任务」也能就地改依赖。
- **诚实边界**：失败是**确定性模拟**（`hash(任务编码 + 期次) % 7 === 3` 判失败），演示时主动讲这一句——换来的是"失败 → 重跑"每次都能重放。

### F3. 调度配置 `/cr-schedule/config`

- **点什么**：看列表里的 Cron（等宽字体）→ 拨一下某行的**启停开关** → 点「新增」，Cron 先填 `0 0 2`（故意三位）再提交。
- **说什么**：**一个任务只保留一条调度**；Cron 是 Quartz **六段**（秒 分 时 日 月 周）；「有状态」的任务串行执行，无状态可并发；
  调度状态只管"自动调度会不会跑它"——**关掉之后仍然可以在手工调度里手动执行**。
- **应该看到**：开关一拨即生效（表格里立刻显示「已关闭」）；Cron 填错时中文报错「Cron 表达式需要 6 段（秒 分 时 日 月 周，如 0 0 2 * * ?），当前 3 段。缺少：日、月、周」。
- **异常分支**：给一个已经有调度的任务再建一条 → 中文拒绝「已经有调度配置了，请直接修改原来那条」。

### F4. 手工调度 `/cr-schedule/manual`

- **点什么**：勾「报表加工汇总」→ 期次选 `202607`（下方自动显示推导出的数据日期 `2026-07-31`）→ 点「批量执行」→ 确认。
- **说什么**：手工调度 = **重跑历史批次**，按「优先级 → 任务编号」顺序跑；数据日期由期次推导；
  只写跑批日志，**不会改填报数据**；前置任务没成功的会落「等待前置任务」而不是照跑。
- **应该看到**：结果区五张卡（生成 4 / 成功 3 / 失败 1 / 等待 0 / 新增行数）+ 逐条明细（失败行红字），
  以及「这批记录已写入批量监控」和**「去批量监控查看」**按钮 —— 点它跳到批量监控并**带着期次筛选**（这条深链是刻意做的）。
- **异常分支**：一组都不勾就点执行 → 中文提示先勾分组（不会静默什么也不做）。
- **诚实边界**：执行结果**只存内存**，刷新页面就清空（页面上写明了）；要留痕就看批量监控里的跑批日志。

### F5. 集群配置 `/cr-schedule/cluster`

- **点什么**：看 4 个节点（1 个 master + 3 个 worker）→ 点「新增」，节点地址先填 `10.20.31.99`（不带端口）再提交。
- **说什么**：集群里只有一个主节点负责任务分发，工作节点承担实际跑批；**离线节点不会再接收到调度**；节点地址格式是 `IP:端口`。
- **应该看到**：地址格式不对时中文报错「节点地址格式应为 IP:端口，如 10.20.31.11:8080（当前：10.20.31.99）」；节点名重复也会被拦。
- **诚实边界**：只校验节点名唯一与地址格式，**不拦"第二个 master"**，也没有心跳与负载上报（状态是静态字段）。演示时别把它讲成高可用调度。

### F6. 公式SQL定制 `/cr-message/sql-custom`（报文配置分组下）

- **点什么**：点任一行的**「试运行」**看 7 项检查全通过 → 点「修改」，把 SQL 改成 `DELETE FROM premium_info` 再点「试运行」→
  再改成 `SELECT * FROM no_such_table` 试一次。
- **说什么**：这里是给监管口径 / 校验规则挂 SQL 公式的地方；**试运行只做静态解析、不执行 SQL**，
  所以既不落数据也不返回结果集，结论是确定性的；引用的表必须先在《报送配置 → 表管理》里登记过。
- **应该看到**：① 正常公式 → 绿色「语法占位检查通过：7 项检查全部通过（未执行 SQL，仅做静态解析）」，并列出占位参数与引用表（含中文表名）；
  ② 写操作 → 不通过「公式只允许 SELECT，检测到写操作关键字：DELETE」；
  ③ 未登记的表 → 不通过「以下表不在《报送配置 → 表管理》的清单里：no_such_table」。
- **诚实边界**：需求文档该章只有一句「用于定义 SQL」，**字段与校验规则都是按通行做法提案**的；试运行没有真实执行计划 / 权限 / 代价估算。

## 九、常见提问与标准回答（背下来）

| 提问 | 回答要点 |
| --- | --- |
| 数据是真的吗？ | **代码是真的，数据是本地种子**：接口、校验、审批流、统计口径都在跑真代码；数据存在浏览器 localStorage，刷新不丢，清缓存回到初始。数字会随你在页面上的操作变化。 |
| 有没有后端？ | 没有。`src/mock/adapter.ts` 是自写的 axios 适配器，`src/mock/handlers/**` 里是"接口实现"，换成真后端时把适配器摘掉即可，页面与 api 层不用改。 |
| 权限是怎么做的？ | 三层：菜单按角色下发（看不到就是看不到）、按钮按权限标识控制（`v-hasPermi`）、**接口层再判一次角色**（这才是真拦得住的一层）。另外还有机构数据范围（列表按登录人过滤）与部门动作权限（能不能报这张表）。 |
| 为什么有些按钮我看不到？ | 因为您的角色没有这个权限标识——这是设计，不是 bug。切管理员账号就能看到。 |
| 数字对不上？ | 每个统计页顶部都写了**口径**；三处数字如果打架就是 bug，我们刻意做到"预检/申请/执行"三个数字同源。 |
| 有没有测试？ | 五个门禁：主链路、增删改查、逐页巡检、按钮权限静态检查、写接口鉴权与只算数不落库。改完代码必须全绿。 |

## 十、演示中容易翻车的点（提前知道）

1. **不要重启 dev server**：改文件走 HMR；重启会让正在演示的页面重新登录。
2. **读数字前等页面落地**：数据是异步填的，提前截图会读到"24 / 7"这种中间态。
3. **改过 mock 种子就要硬刷新**：否则读到的还是旧 localStorage（`SEED_VERSION` 不匹配才会重播种）。
4. **弹窗里的红条是"提示"不是"报错"**：脱敏放行前的复算差异、审批状态变化提示都是刻意的。
5. **要演"失败"就用种子里留好的失败样本**：监管回执接口超时、灾备主机停用、.exe 附件被拒、停用密钥轮换被拒、发送失败的提醒邮件——都留好了，不用现场造。
6. **一次只演一条动线**：全量 104 条路由逐页点会超时，用 `pnpm e2e:pages` 替代。
7. **改过 mock 种子后，任务调度的演示数据会重置**：跑批日志的四种状态（成功 / 失败 / 等待前置 / 运行中）来自种子，
   在现场点过「立即执行」「手工调度」之后会**多出新的记录**——这不影响演示（四态仍在），但别拿"总记录数"当固定数字讲。
