# 页面开发规范（CR 监管报送模块）

> 目的：让 `src/views/cr/**` 下的每个页面长得一致、写得一致，能被 mock 引擎自动接管。
> **样板页（照抄这个）**：`src/views/cr/task/template/index.vue` + `TaskTemplateForm.vue`
> **样板 API**：`src/api/cr/task/template/index.ts`
> **样板 mock**：`src/mock/handlers/cr.ts` + `src/mock/db/cr.ts`

---

## 一、目录与命名约定

| 内容 | 位置 | 命名 |
| --- | --- | --- |
| 页面 | `src/views/<模块>/<页面>/index.vue` | 目录名小驼峰，如 `src/views/cr/task/auditLocal/index.vue` |
| 表单弹窗 | 同目录 `XxxForm.vue` | 如 `TaskTemplateForm.vue` |
| 其他弹窗 | 同目录 `XxxDialog.vue` | 如 `TaskTemplateReportDialog.vue` |
| API | `src/api/cr/<模块>/<页面>/index.ts` | 与 views 路径镜像 |
| mock 处理器 | `src/mock/handlers/<域>.ts` | 见下 |
| mock 种子数据 | `src/mock/db/<域>.ts` | 见下 |

`defineOptions({ name: 'CrXxx' })` 必须与 `src/mock/db/menu.ts` 里的 `componentName` **完全一致**（keep-alive 依赖它）。

**路径 vs 路由**：菜单是「顶级目录绝对路径 + 子级相对段」，所以页面真实 URL 是
`/cr-task/template`、`/cr-meta/subject` 这种形式，**不是** `/cr/task/template`。

## 二、API 模块写法

统一 `import request from '@/config/axios'`，标准 CRUD 六件套 + 导出：

```ts
export const getXxxPage = (params: any) => request.get({ url: '/cr/xxx/page', params })
export const getXxx = (id: number) => request.get({ url: '/cr/xxx/get?id=' + id })
export const createXxx = (data: XxxVO) => request.post({ url: '/cr/xxx/create', data })
export const updateXxx = (data: XxxVO) => request.put({ url: '/cr/xxx/update', data })
export const deleteXxx = (id: number) => request.delete({ url: '/cr/xxx/delete?id=' + id })
export const deleteXxxList = (ids: number[]) =>
  request.delete({ url: '/cr/xxx/delete-list', params: { ids: ids.join(',') } })
export const exportXxx = (params: any) => request.download({ url: '/cr/xxx/export-excel', params })
```

接口前缀统一 `/cr/**`，**不要**带 `/admin-api`（baseURL 已处理）。

## 三、Mock 处理器写法

### 1. handler 是自动发现的

`src/mock/index.ts` 用 `import.meta.glob('./handlers/**/*.ts', { eager: true })` 自动加载。
**新增接口只需要新建文件**，不要去改 `src/mock/index.ts`。

### 2. 优先用 `registerResource` 批量注册标准 CRUD

```ts
import { registerResource } from '../resource'
import { likeAny } from '../util'
import { xxxTable } from '../db/crXxx'

registerResource({
  prefix: '/cr/xxx',
  table: xxxTable,
  sort: (a, b) => b.id - a.id,
  filter: (row, params) =>
    likeAny(row, ['code', 'name'], params.keyword || params.name) &&
    (params.status === undefined || params.status === '' || Number(row.status) === Number(params.status)),
  toSimple: (row) => ({ id: row.id, name: row.name }),
  // 列表行投影：只在 /page 与 /list 生效（详情接口仍返回原样行）——用来剥离大字段或补现算字段
  toListRow: (row) => ({ ...row, daysLeft: daysUntil(row.effectiveTo) }),
  exportColumns: [
    { field: 'code', label: '编码' },
    { field: 'name', label: '名称' },
    // 枚举列 / 数组列用 formatter 换成中文：导出应该是给人看的，不是原始码值
    {
      field: 'status',
      label: '状态',
      formatter: (row) => (Number(row.status) === 1 ? '启用' : '停用')
    },
    {
      field: 'actions',
      label: '允许动作',
      formatter: (row) => (row.actions || []).join('、')
    }
  ]
})
```

它会自动注册：`/page`、`/list`、`/simple-list`、`/get`、`/get/:id`、`/create`、`/update`、`/delete`、`/delete-list`、`/export-excel`。

> **注册顺序有讲究**：`src/mock/route.ts` 里**后注册的同路径路由会覆盖先注册的**。所以自己写的
> `onGet('/xxx/simple-list', ...)`（想要更瘦的下拉投影）、或想给删除加跨表引用校验的 `onDelete`，
> 都要写在 `registerResource` **之后**；写在前面会被资源自带的实现盖掉，而且不报错。
> 反过来，如果你希望资源的默认实现生效，就别在它后面重复注册同路径。

自定义接口用 `onGet/onPost/onPut/onDelete`，路径支持 `:param`：

```ts
import { onGet, onPut } from '../route'

onGet('/cr/task-template/report-list', (ctx) => { ... })
onPut('/cr/task-template/update-reports', (ctx) => {
  const { id, reportIds } = ctx.body || {}
  ...
  return true
})
```

### 3. 报错方式

**直接 `throw new Error('中文提示')` 即可。**

adapter 会把 handler 抛出的异常统一包成 `{ code: 400, msg: '中文提示' }`，
脚手架拦截器对 400 会原样把 msg 弹成通知。**不要抛 `code: 500`**——拦截器会把
500 替换成通用的「系统异常」文案，业务提示就丢了（`src/mock/adapter.ts` 里有注释说明）。

> 参考 `src/mock/handlers/cr.ts` 里 `update-reports` 的频度校验分支。

### 4. 种子数据用 `defineTable`

```ts
import { defineTable } from '../store'

export interface XxxRow { id: number; code: string; name: string; status: number; createTime: string }

export const xxxTable = defineTable<XxxRow>('cr.xxx', [
  { id: 1, code: 'A001', name: '示例', status: 0, createTime: '2026-09-01 09:30:00' }
])
```

表名全局唯一，会持久化到 `localStorage['cr-mock:table:cr.xxx']`。
**种子数据必须是中文业务语境的真实感数据**：公司统一用「华信人寿保险股份有限公司」，
机构用「总公司 / 北京分公司 / 上海分公司 / 江苏分公司 / 浙江分公司 / 山东分公司 / 广东分公司」，
期次统一 `202608`，时间用 `2026-09-xx`。

## 六、必须自查的三件事

1. **权限标识**：页面里写的每个 `v-hasPermi` 都必须在 `src/mock/db/menu.ts` 的 `BUTTONS`
   里有对应项（key 是 `路由 key`，如 `cr-meta/subject`）。漏了会导致按钮**整个消失**。
   > 如果本次要新增页面，BUTTONS 由统一维护者补，页面里按 `cr:<模块>-<页面>:<动作>` 命名即可。
   >
   > **按钮级角色收窄**：`BUTTONS` 的元组支持可选的第三个元素
   > （`['审核', 'cr:collect-import:audit', ADMIN_ONLY]`），用于「页面开放给多个角色、
   > 但某个按钮只给管理员」的场景。不写就跟随页面角色。
   > 改了这个元组记得跑 `pnpm e2e:perms` —— `scripts/check-permissions.mjs` 是按正则扫元组的，
   > 元组写法太花（第三个元素既不是数组字面量也不是简单标识符）会让它漏扫、把已授权的标识误报成缺失。
2. **编译通过**：`curl -s -o /dev/null -w "%{http_code}" http://localhost:5173/<文件路径>` 返回 200。
3. **无控制台异常**：`pnpm e2e` 必须保持 10/10 通过。

### 追加：数据权限要落在 handler 里，不能只藏按钮

页面上的 `v-hasPermi` / `v-if` 只是"看不见"，直接调接口照样能改数据。
凡是带数据权限的功能（如导入权限 `cr.importAuth`），都要在 handler 里再判一次
（见 `src/mock/handlers/crCollect.ts` 的 `assertImportAuth()`：拿 `currentUser(ctx)` 解析登录人 →
`effectiveImportAuth()` 算出生效规则 → 不通过就 `throw new Error('中文原因')`）。

配套约定：页面上的"我的权限"横幅必须读**同一个接口**（如 `GET /cr/collect-import/my-auth`），
不要在前端自己算一遍 —— 否则会出现"横幅说能导、提交却被拒"这种自相矛盾的演示事故。

### 追加：浏览器内的文件解析（零依赖）

- **文本 / CSV**：`src/views/cr/collect/import/parseFile.ts`，核心是 `parseImportRows(rows: string[][], config)`
  —— CSV 与 XLSX 共用同一套校验规则，别各写一套。
- **XLSX**：`src/views/cr/collect/import/xlsx.ts`，自己解 ZIP（`DecompressionStream('deflate-raw')`）+ 读 sheet XML，
  **不需要任何 npm 依赖**；日期单元格归一化成 `yyyy-MM-dd` 后由 `rowsFromXlsxSheet()` 按模板格式改写。
- **附件**：Demo 没有文件服务，页面把文件读成 data URL 交给 mock 存库（单文件 ≤ 1MB，见
  `MAX_ATTACHMENT_SIZE`），这样"下载附件"拿到的是真实内容而不是假地址。真实项目里换成文件服务地址即可。

### 追加：会「改写业务数据」的动作必须走审批（脱敏审批流的约定）

数据脱敏最初是"点执行就改写填报数据"。现在改成：**页面上的入口只能提交申请，真正执行发生在审核岗放行之后**
（`/cr/desens-execute/run` 保留在服务端作为执行内核，页面上已经没有直接调用它的按钮）。

要照这个模式再做一个动作时，按下面这套照搬：

1. 表上加审批字段：`status`（`6 待审核 / 7 已驳回`）、`applyUser / applyTime / auditUser / auditTime / auditRemark`。
2. 申请单**复用同一条业务记录**（这里是 `cr.desensTask`），不要另建"申请表" —— 否则"提交了什么"和"执行了什么"会对不上，
   且 `runDesensitize({ task })` 支持把已存在的待审核记录直接推进到执行态。
3. 提交申请时**只算不动**：把预检结果（计划改哪些行、哪些字段）存进申请单，页面上明确写「这一步不会改任何数据」。
4. 审核通过 → 在 handler 里调执行内核 → 把执行结果写回同一条记录（状态、明细、消息里带上「经 X 审核通过后执行」）。
5. 驳回必须填原因（前端 `el-form` 校验 + handler 再判一次），并保留记录为「已驳回」而不是删掉。
6. 撤回只允许申请人本人或 `ROLE_CODE.ADMIN`，且只在「待审核」状态下可撤。
7. 页面上要有「去审批」的跳转（带 `query.keyword = batchNo`，让审批页打开就筛到这一条），
   否则演示时来回找单子会讲不清楚。

### 追加：只读型动作要说清楚「不改数据」

「数据拆分」只对填报明细做分组、产出报送包清单，**不复制行、不改写任何字段值**。
这类动作的页面必须在顶部用一句话写明，并在执行结果的提示里再写一遍 ——
否则用户会默认"拆分 = 复制一份数据"，演示时第一个问题就是这个。

### 追加：组件坑与文件风格（本轮踩过，别再踩）

- **`<ContentWrap>` 只有传了 `title` 才会渲染 `#header` 插槽**（内部是 `v-if="title"`）。
  在 `#header` 里放标签/统计又忘记传 `title`，内容会被**静默吞掉**，页面不报错、只是什么都不显示。
- **本仓库 `.ts` 带分号、`.vue` 不带分号**（prettier 风格）。用脚本给 `.vue` 打补丁时，
  `old_string` 必须按文件里的真实文本（结尾**不要**写分号）写，否则 `str.replace` 静默不生效 ——
  改完一定要断言（`assert old in s`）并回读文件确认。
- **验证"数据有没有真的变"要走 `@/api/**` 或直接读 localStorage**：
  `import('/src/mock/db/crData.ts')` 可能拿到与页面不同的模块实例，会得出"一行都没变"的假结论。
- **同一个「机构 × 报表 × 数据项」的多条配置**：只有一条生效（优先级小的、再按 id 早的），
  所以配置列表必须把"本条到底生不生效"标出来（`GET /cr/desens-field/decisions` → 生效中 / 被覆盖 / 不在生效期 / 已停用），
  否则用户新增一条配置后会以为已经生效，而实际被老配置盖住 —— 这类"以为脱了其实没脱"的误会必须由系统主动讲清楚。

### 追加：新增一个"过滤维度"要贯穿全链路（收尾轮的教训）

字段配置先加了「生效期」，收尾轮又加了「适用期次」（`periods`）。两次的共同点是：
**过滤条件绝不能只落在"列表标签"上，必须同时落到四个地方**，否则会出现"页面说生效、执行却没生效"这类最坏的结果：

1. 选择生效配置的引擎函数（`effectiveDesensFields(orgId, reportId, today, period)`）；
2. **预检**与**提交申请**（`precheckDesens` / `applyPlanOf`）—— 数字必须一致；
3. **真正执行**（`runDesensitize`）—— 漏了这一处，预检与实际就会是两张皮；
4. **排除原因**（`excludedDesensFields`）—— 页面上要能回答"我明明配了，为什么没动？"，
   理由要具体到数字（如「仅适用 202607 期次（本次 202608）」）。

还有一个连带坑：**"配置列表"没有"这次跑哪一期"的上下文**。
所以「生效判断」列对写了期次的配置只能说「生效中（仅 X 期次适用）」，**不能**据此报"生效/不生效"，
否则同一行会随执行期次变脸。判断类列要么给足上下文，要么只描述适用范围。

### 追加：能复用的生成口径不要写第二套（拆分包文件的做法）

「数据拆分」收尾时要给每个包一个**真实可下载的文件**，做法是**直接复用「一键报送」的生成器**
（`planReportFile()` / `buildSubmitFile()`，格式/分隔符/表头行数取机构《报送文件配置》），而不是在拆分模块里
另写一套 CSV 拼装。理由与「报文下载名不副实」那次教训相同：

- 列表上显示的**文件大小 = 真正下载到的字节数**（`blob.size`），两边同源；
- 下载接口里再自检一次（`file.bytes !== row.fileSize` 就按真实内容回写并 `console.warn`），
  避免历史数据对不上时静默糊过去；
- 文件名沿用同一套命名（`HX_机构码_报表码_期次_包名.后缀`），演示时能一眼看出"这是同一份报文切出来的分片"。

### 追加：审批类页面要留"动作时间线"，不能只留最后一态

`cr.desensTask` 早期只有 `auditUser / auditTime / auditRemark`（最后一个人、最后一次意见）。
收尾轮补成 `auditTrail: [{ action, actionLabel, user, time, remark }]`，提交 / 审核通过 / 驳回 / 执行 / 还原 逐条追加：

- **动作中文名由服务端给**（`DESENS_TRAIL_LABEL`），页面不再维护第二套映射；
- 时间线两处都放：**审批弹窗**（审核岗要看到谁提交、之前有没有被驳回过）与**日志详情抽屉**；
- **"单据会被删掉"的动作**（撤回）不留库，但要在返回值里带上留痕，页面当次提示里能说清；
- 种子数据也要有留痕，否则演示时点开历史批次是一片空白。

### 追加：同范围多条配置要靠"显式优先级"，不要靠隐式约定

`cr.splitRule` 最初同范围多条规则按"**后建的先生效**"——这是隐式约定，配置一多就没人说得清谁生效。
收尾轮加了 `priority`（0~999，缺省 50，非法值给中文错误），判定顺序固定成
**范围（机构 > 全局、报表 > 全部）→ 优先级小的 → 后建的**，列表把优先级显示出来。
做同类"多条规则命中一条"的设计时，直接照这个顺序来：范围 → 显式优先级 → 兜底规则（新建的优先），
不要发明第四种隐式规则。

### 追加：藏按钮拦不住接口 —— "会动数据"的写接口必须再判一次角色

第三轮独立对抗式审核推翻了一条我们原本以为成立的声明：脱敏的审批流在**页面上**是完整的
（填报/复核/审核岗看不到「脱敏执行」入口，`runDesens` 也没有任何页面调用），
但 `/cr/desens-execute/run`、`/approve`、`/reject` 在 handler 里**一个角色都没判** ——
填报岗（甚至 `isToken:false` 的匿名请求）只要拿到接口地址，就能直接放行并真实改写填报数据，
`operator / auditUser` 还会如实记成那个人的名字。拆分侧同理（谁都能建规则、执行拆分）。

约定（新写任何模块都照做）：

- **页面权限与接口权限是两件事**：`v-hasPermi` 与菜单只解决"看不看得见"，接口权限在 handler 里判。
- **判角色的工具只有两个**：`assertRoles(ctx, [ROLE_CODE.ADMIN, ...], '动作中文名')`（脱敏 handler）
  与 `assertAdmin(ctx, '动作中文名')`（拆分 handler）——不要各写一份 `roleIds` 遍历。
- **`registerResource` 的写操作传 `guard`**：`guard: (ctx, action) => assertAdmin(ctx, '拆分规则' + action)`
  （`action` 是 `新建/修改/删除/批量删除`），因为 `beforeCreate/beforeUpdate` 拿不到 `ctx`。
- **只读接口不锁**：审批岗需要看列表 / 统计 / 复算，锁了会把审核岗关在门外；判角色只针对写。
- 报错给人看：`「执行拆分」仅系统管理员可操作（当前账号：张天报）`，既说清动作也说清当前身份。
- **新增写接口后，用"冒充别人"的方式自测一遍**（`--user=filler` + `Authorization: 'Bearer mock-token.2.x'`），
  不能只在页面里点一遍就算验证过；并把这条接口补进 `scripts/e2e/auth.mjs` 的 `WRITES` 清单（`pnpm e2e:auth`）——
  第一轮补鉴权时就漏了两个 toggle（`/cr/desens-rule/toggle`、`/cr/desens-field/toggle`），
  未登录能把脱敏"静默关掉"，是复验时才抓到的。清单之外的写接口等于没验。
- **先验身份再验权限**：探针脚本要先跑一次身份自证（`/system/auth/get-permission-info` 看昵称），
  确认令牌真的代表它声称的人。复验时曾把 header 写成字符串 → axios 忽略它、回落到已登录的管理员，
  差点把"未登录也能放行"误报成漏洞。
- **口径要按"这一层能保证什么"写**：mock 的 token 没有签名（`Bearer mock-token.<userId>.x`），
  所以文档里写"按前端携带的 userId 判角色"，不写"接口层鉴权 = 安全边界"。

### 追加：单据上的数字是"提交那一刻"的快照 —— 放行前要复算

审批流的坑不在于"谁批的"，而在于**申请单上的数字会过期**：申请时算好"预计脱敏 103 个字段值"，
审核岗过半小时才点通过，中间有人补录/导入/还原过数据，实际就只改了 102 个 ——
如果界面展示的仍是旧数字、批次还写"执行成功"，这条审计线索就是假的。

做法（`recheckDesensApply()` + `GET /cr/desens-execute/recheck`）：

- 打开审批弹窗时**复算一次**（只读接口，不算写操作），不一致就在顶部给**红条**写明
  「申请时预计 N（X 行）→ 现在预计 M（Y 行）」；数字一致时不显示任何东西，避免噪音；
- 复算失败（配置被删、数据被清空）也要红条提示原因，不能静默当作"没变化"；
- 放行时把差异写进**审批意见与留痕**（`auditRemark` + `auditTrail`），批次记录里能查到当时差多少；
- 复算**只提示不阻断**：放行与否是审核岗的判断，系统不替他做决定，但必须把事实摆在他眼前；
- **复算要比"口径"而不只是比数量**：只比总数会漏掉"换成另一条规则 / 换了命中条件但行数刚好一样"——
  实测把某字段的掩码规则换成哈希（34 行 ⇒ 34 行）时旧实现报"无变化"，审核岗看到"没变"却放行了另一套。
  做法是逐字段比签名（数据项 + 规则编码 + 规则参数 + 命中条件）并把 `diff[]` 逐条显示；
- **再往下一层要能发现"值被动过"**：行数与口径都没变、只是两行原文互换了，签名比不出来。做法是提交时存一份
  **原文指纹**（行标识 + 会参与改写的列值，按行排序后取哈希），放行前再算一次。
  必须排序后再哈希 —— 填报数据保存 / 导入后底层行序可能变，不然保存一次就误报一次（实测踩过）。

同类改造清单：任何"先提交、后处理"的单据（导入批次审核、补录申请、报送批次），
只要处理时会重新读数据，就应该在放行前复算并展示差异。

### 追加：同一个统计口径只写一处 —— 别让页面上的数字互相矛盾

「按命中条件跳过 N 行」原来在四个地方各写了一遍 `Math.max(...)`（预检 / 申请单 / 批次 / 种子），
两个字段各跳 33 行时页面显示 33、实际被跳过的行是 42 —— 数字本身不假，但**口径是错的**，
演示时被审核子代理用手工计数一眼抓出来。

约定：

- 口径抽成**纯函数**（`countRowsSkippedByCondition(rows, items)`），调用点只传数据不写逻辑；
- 页面上带歧义的数字要**写清口径**（并列成「按命中条件跳过 N 行（至少一个字段不满足）」），
  而不是留一个可以被两种解释读的短标签；
- 同一批数据在**预检 / 申请单 / 执行结果**三处出现的数字必须同源同值 —— 改口径时三处一起验证
  （`t3/t10` 那类"手工计数 vs 接口返回"的对照脚本是有效的验收方式）。

### 追加：P2 轮的六个坑（2026-09-12 深夜轮）

**1. `beforeUpdate` 只返回"可改字段"会丢 id，导致修改 100% 失败。**
   `table.update(payload)` 是按 `payload.id` 匹配的，而 fill 型 `beforeUpdate` 习惯写成
   `"挑出可改字段 + updateTime"`（不含 id）→ 接口报「记录不存在：id=3」。
   已在 `src/mock/resource.ts` 统一兜底：`{ ...handled, id: Number(body.id) }`。
   **新写 handler 不用再管这件事**，但自己写 `onPut`（不走 registerResource）时仍要保证 payload 带 id。

**2. 守卫的报错文案必须含「可操作」三个字。**
   `pnpm e2e:auth` 判"这条请求被拒了没"看的是通知标题里的中文原因，正则匹配 `/可操作|需要先登录|登录已过期/`。
   自己写守卫时用 `assertRoles/assertAdmin/assertLogin`（`src/mock/handlers/guards.ts`，文案已符合——
  `assertLogin` 的「需要登录后操作」已进门禁正则，之前它是门禁盲点），
   不要另造一套只说「无权限」的措辞 —— 门禁会把它判成"放行"。

**3. 「看着像查询」的 POST 要自证不落库。**
   报表功能的两个预览（`/cr/report-dataset/preview`、`/cr/report-design/preview`）用 POST 只是因为要传对象，
   它们是纯计算：补进 `scripts/e2e/auth.mjs` 的 `COMPUTE` 清单后，门禁会用**整库行数快照**证明一行都没写。
   反过来，像「连接测试」「心跳检测」这种看着像查询、实际会写回结论的接口，要当**写接口**处理（守卫 + 进 `WRITES`）。

**4. 统计页不要建"统计结果表"。**
   10 个统计查询全部当场从业务表汇总（`src/mock/db/crStat.ts` 的 `statPayload()`），页面只传 `code + 机构/报表/期次`。
   好处是"改一条业务数据 → 回来看统计，数字跟着变"这条链路是真的；一旦落成独立表就会和业务数据脱钩（第一轮审核就报过这个问题）。
   每个查询必须给 **口径说明（`note`）**，并在页面上直接展示 —— 口径是按通行做法提案的要如实标注。

**5. 数据集的"预览取数"要有真实落点。**
   数据集种子里的 `previewSource` 不是自由字符串，而是 handler 里一张`来源标识 → 真实 mock 表`的映射表（`PREVIEW_SOURCES`）；
   新建/修改时会校验它是否在表里，取数时直接读那张表的当前数据。新加数据集来源 = 往映射表里加一条，不要另造一份演示数据。

**6. 去重是"跑批类"功能的核心，要能被演示证明。**
   自动提醒的「立即执行一次」按 **规则 + 单据 + 接收人** 去重：第一次生成 N 条、第二次生成 0 条且提示"跳过 M 条"。
   演示时"点两次"比任何解释都有效；这也是判断"提醒是不是真的在扫数据"的最快办法。
