基于开源脚手架 [yudao-ui-admin-vue3](https://gitee.com/yudaocode/yudao-ui-admin-vue3) 搭建的**监管报送业务演示系统**。

> 本 Demo **只参考**《统一监管保送产品说明》里的功能逻辑，界面全部用脚手架现有组件重新表达，
> 没有照搬原产品的任何界面资产。

> **版本库**：本目录已 `git init`（分支 `main`），首个提交是「初始提交：统一监管报送平台（纯前端演示，零后端）」，
> 跟踪 846 个文件。`node_modules/`、`dist/`、`.pnpm-store/`、脚手架只读参考副本 `.yudao-ref/`
> 与自动生成的 `auto-*.d.ts` 按 `.gitignore` 排除；`.env.local` 是运行所需的 mock 环境配置，已纳入跟踪（无密钥）。

> **公开仓库**：<https://github.com/junfengM/cr-report-demo> —— 由 `node scripts/publish-public.mjs` **净化后**发布：
> 第三方产品文档及其正文摘录不在其中，只保留自己写的代码与文档（详见 `docs/00-项目上下文.md` 的「公开发布」）。

> **直接下载（不想装环境就看这里）**：<https://github.com/junfengM/cr-report-demo/releases/latest>
> · `cr-report-demo-win-x64.zip`：**Windows 免安装**，解压 → 双击 `start-demo.bat` → 浏览器自动打开（内置 Node 运行时，**对方零安装、不联网**）
> · `cr-report-src.zip`：源码包，装 Node ≥ 20.19 + pnpm 后 `pnpm install && pnpm dev`（包内附「安装与启动.md」）

## 一、这个 Demo 是什么

- **纯前端**：不含后端服务与数据库。所有接口由项目内自写的 axios mock adapter 接管，
  前台操作结果保存在**浏览器 localStorage**（key 前缀 `cr-mock:`）。
- **零新增依赖**：mock 引擎内核是自研的 570 行（`adapter` + `route` + `store` + `resource` 四个文件；连 `index` 和 `util` 一起算 759 行，`wc -l` 实测），没有引入 mockjs / msw / json-server 等任何东西。
  种子数据与 handler 另有约 35,900 行（db 22,322 + handlers 13,591），那是业务数据不是引擎。
- **依赖还做了瘦身**：用 `node scripts/scan-deps.mjs` 逐条取证后删掉 26 个零引用包（bpmn-js / dhtmlx-gantt / livekit-client / video.js 等），
  **105 → 79 个依赖**；剪枝后的 `node_modules` 上 `pnpm build:demo` 仍然通过，产物里也 grep 不到这些包（详见 `docs/00-项目上下文.md` 的 ADR D12）。
- **业务样例数据**：机构、报表、任务、校验规则等全部是代码里的种子数据，
  虚构主体为「华信人寿保险股份有限公司」，报送期次统一 `202608`。
- **用户 / 角色 / 菜单 / 权限**：同样是代码 mock 数据，登录链路完全复用脚手架原生实现
  （`POST /system/auth/login` → `GET /system/auth/get-permission-info` → 动态注册路由）。

## 二、快速开始

```bash
# 环境要求：Node >= 20.19.0，pnpm >= 8.6.0
pnpm install
pnpm dev            # http://localhost:5173
```

也可以只看静态产物（不需要 dev server）：

```bash
pnpm build:demo     # 构建（必须用这个命令，原因见本节末尾）
pnpm preview:dist   # http://127.0.0.1:4188
```

> ⚠️ **不要用脚手架自带的 `pnpm build:dev`**：它走 `--mode dev`，加载的是上游的 `.env.dev`
> （接口地址指向芋道的演示环境）。Vite 环境下，`.env.[mode]` 会覆盖 `.env.local`，
> 用 `build:dev` 打出来的包会卡在登录页且没有任何报错提示，很难排查。
> 本 Demo 的开发与构建统一使用 `env.local` 这一套环境变量，即 `pnpm dev` 与 `pnpm build:demo`。

## 三、自检（交付质量门禁）

项目自带五个自检脚本，用**无头 Chrome 真实驱动浏览器**（不依赖 playwright / puppeteer）：

```bash
pnpm e2e          # 主链路：登录 → 权限 → 菜单 → 列表 → 弹窗，10 项断言      → 10/10
pnpm e2e:crud     # 增删改查 + 刷新后持久化，5 项断言                        → 5/5
pnpm e2e:pages    # 逐页巡检：遍历登录态下发的 104 条路由                    → admin 104/104
                  #                                                            （filler 11/11 · reviewer 13/13 · auditor 12/12）
pnpm e2e:perms    # 静态检查：v-hasPermi 是否都已在 mock 菜单里授权          → 0 缺失（用到 369 / 授权 435）
pnpm e2e:auth     # 判角色：133 条写接口 × 冒充四个身份逐个探，必须全被拒    → 287/287

# 两个"证据型"脚本（不驱动浏览器，输出可复核的数字）
node scripts/scan-deps.mjs    # 依赖引用扫描：A. 真正无引用 / B. 有间接证据（附保留理由）
node scripts/audit-writes.mjs # 写接口鉴权审计：A. 没有接口层守卫 / B. 没进门禁清单，按文件分组计数
```

- `pnpm e2e:pages --user=filler` 可以指定角色巡检，验证权限隔离。
- `pnpm e2e:auth` 会先做**身份自证**（确认令牌真是它声称的人）再探权限；新增写接口必须补进它的 `WRITES` 清单。
- `pnpm e2e:pages --filter=cr-meta` 可只巡检某个模块。
- `pnpm e2e` 需要 dev server 已在运行。
- 换机器时若找不到浏览器，用 `CHROME_BIN` 指定可执行文件；用 `APP_URL` 指向其他地址。
- 调试单个接口：
  `node scripts/e2e/eval.mjs "<任意 JS 表达式>"`，登录后在页面上下文里执行；
  加 `--shot=文件名.png --size=1440x1100` 还能顺便截图。

> **`pnpm e2e:perms` 很关键**：`v-hasPermi` 命中未授权的权限标识时，按钮会**直接消失且控制台不报错**，
> 只有这个静态检查能发现。

> **代码风格怎么验**：`pnpm lint:format:check`（prettier）是好的，本项目所有新增文件都过了它。
> `pnpm lint:eslint:check` 目前**启动即报错**（`@unocss/eslint-plugin@66.6.8` 漏声明了 `@typescript-eslint/types`，pnpm 严格布局下解析不到）——
> 这是上游插件的问题，**与本次依赖瘦身无关**（用瘦身前的 lock 做对照组同样失败，见 `docs/00-项目上下文.md` 已知简化 38）。

`docs/screenshots/` 里有 23 张真实运行截图（工作台、数据填报、校验结果、数据审核、报文生成、
脱敏结果查询、机构维护、采集与取数、脱敏审批与拆分、任务调度四态、公式SQL 试运行等），不启动项目也能先看效果。

> **截图/取值要等数据落地**：页面是先渲染空态再填数据的，在请求回来之前读 DOM 或截图会拿到中间态
> （同一个页面可能读出 24、7 这类互相矛盾的数字）。用
> `node scripts/e2e/eval.mjs "new Promise(r=>setTimeout(()=>r('settled'),3000))" --url=/index --shot=x.png`
> 先等 3 秒再截。发现数字对不上时，先怀疑读取时机。

## 五、关键实现说明

### 1. 请求拦截：替换 axios adapter

```ts
// src/mock/index.ts
service.defaults.adapter = createMockAdapter()
```

好处是 `src/api/**` 与所有页面的调用方式**一行都不用改**，将来要接真实后端，
把 `.env.local` 里的 `VITE_BASE_URL` 改回后端地址、`VITE_MOCK_ENABLE=false` 即可。

### 2. 数据持久化

```ts
export const orgTable = defineTable<OrgRow>('cr.org', [ /* 种子数据 */ ])
```

每张表按 `localStorage['cr-mock:table:<表名>']` 独立存储，首次访问时写入种子数据。
种子结构变更时改 `src/mock/store.ts` 里的 `SEED_VERSION` 会自动重建。

### 3. 接口报错约定

handler 里直接 `throw new Error('中文提示')`，adapter 会包成 `{ code: 400, msg }`，
脚手架拦截器原样弹出提示。

> 注意**不要用 `code: 500`**，拦截器会把 500 替换成通用的「系统异常」文案，业务提示会丢失。

### 4. 菜单按「阶段 + 实现状态」下发

`src/mock/db/menu.ts` 里每个页面可以标 `implemented: false`，未实现的页面不会出现在侧边栏，
演示时不会点进空白页。页面做完后用 `node scripts/enable-menus.mjs <组件路径前缀>` 启用。

同一个文件里的 `roles` 决定该菜单对哪些角色可见（`routeTreeForRoles()` 递归裁剪），
`BUTTONS` 决定页面内按钮的权限标识。三者同源，所以"菜单能看见但按钮消失"这类问题
可以在开发期被 `pnpm e2e:perms` 拦住。

## 六、演示动线建议

> 逐页的「点什么 / 说什么 / 应该看到什么 / 异常分支」在 **`docs/02-演示脚本.md`**（五条动线 + 常见提问标准回答 + 翻车点清单）。
> 下面是压缩版动线，按报送业务的真实链路走一遍最能体现系统能力：

1. **`admin` 登录** → 工作台看本期（202608）总体进度与节点跟踪
2. **报送配置管理** → 机构维护 / 主题域 / 表 / 列，看报送的元数据底座
3. **`filler` 重新登录** → 数据填报：改单元格、插入行、数据校验（错误行标红）、保存
4. → 批量提交：校验未通过的不允许提交
5. **`reviewer` 重新登录** → 复核操作 / 本级审核 / 上级审核 / 打回
6. **`auditor` 重新登录** → 数据审核：审核面板里看脱敏后的明细，通过或打回
7. → 脱敏结果查询：核对脱敏前后
8. → **报文配置**：报表定制（勾选该报表要上报的字段）→ 报文信息管理（看报文结构与真实报文样例）
   → 报文集配置（点「生成报文」，会真实写入报文上报状态）
9. → 一键报送：报文状态查询（能看到上一步生成的报文，失败重报、下载回执）→ 数据报送清单
10. → **数据采集**：采集方式配置（先点行上的『连接测试』探一次源系统：通的话报握手耗时与预计可抽取行数，
    右上角「取数记录」能看到这次测试的任务号、追踪号与请求参数；再选一条「系统直连」点『立即采集』，
    会真实生成取数任务 + 导入批次）
    → 数据导入（选机构/报表/期次 →「下载导入模板」→ 上传 **CSV / TXT，或直接传 .xlsx**
    —— Excel 在浏览器里解析，日期列自动归一化，不用再另存为 CSV → 解析 → 确认入库；
    页头横幅显示的是当前账号在该「机构 × 报表」上**真正生效**的导入权限，与后端拦截同一条规则）
    → 导入审核（需要审核的批次在这里通过/驳回）→ 导入日志（六类动作的流水）
    → 数据补录（申请 → 上传附件（可预览 / 下载 / 删除，附件真的能下下来）→ 审核 → 执行补录，
    会直接跳到数据填报页看结果）
    **导入权限怎么演示**：`filler` 也能进「数据导入」（填报岗才是真正传文件的人）；先用 admin 在「导入权限」里
    把填报岗那条改成「允许导入 = 否 / 单批上限 = 2 行」，再以 `filler` 登录 —— 横幅变红、导入按钮消失，
    直接调接口也会被中文提示拦住（权限落在 mock handler 里，不是只藏按钮）。
11. → **数据脱敏**（**先切回 admin 登录**——规则/字段/执行/日志四页是管理员专属；「脱敏审批」管理员与审核岗都能进）
    - 脱敏规则配置（看「证件号掩码 前3后4」的示例）→ 脱敏字段配置（机构 × 报表 × 字段 → 规则，
      真正参与判定的配置：**生效期**看「江苏分公司 × BX002 证件号码」那条已过期（回落到掩码配置）、
      「上海分公司 × BX012 证件号码」那条未生效；**适用期次**看「江苏分公司 × BX011 保单号」那条只适用 202607
      （切到期次 202608 预检，它出现在「本次不参与的配置」里）；**命中条件**看「北京分公司 × BX001 证件号码」配了 `销售渠道 = 银保`）
    - 脱敏执行（北京分公司 / 人身险公司商保年金业务统计表 / 202608 → 预检：42 行、将脱敏 92 个字段值、
      **按命中条件跳过 33 行** → 点「提交执行申请」填申请说明）
      ⚠️ 执行前要审批：**提交申请不会改任何数据**，只落一条「待审核」申请单
    - **切到 `auditor` 登录** → 数据脱敏 → 脱敏审批（默认筛「待审核」，能看到 admin 刚提交的那条；
      审核弹窗底部有**留痕时间线**：谁提交、什么时候、申请说明是什么）→ 审核通过
      （想演示「申请单数字会过期」：提交申请后回数据填报页改掉一行再回来点「审核通过」，
      弹窗顶部会出现**红条**「申请时预计 N → 现在预计 M」，放行后这条差异会写进审批意见与留痕）
      → 系统在这一刻才真正执行脱敏（通过后可切回 admin 在脱敏日志里看结果、必要时还原）

## 八、换电脑 / 交付给别人（可复制）

本项目是**纯前端 + 浏览器本地数据**的 Demo，所以"搬到别的电脑"有两种形态，一条命令都能生成：

```bash
node scripts/make-release.mjs          # 重新构建 → 生成两个包到 release/
node scripts/make-release.mjs --skip-build          # 复用现有 dist，不重新构建
node scripts/make-release.mjs --no-node             # 演示包不带 Node 运行时（对方自己装 Node）
```

| 包 | 给谁 | 对方需要什么 | 体积（实测） |
| --- | --- | --- | --- |
| `release/cr-report-demo-win-x64.zip` | **只看演示的人** | **什么都不用装**：解压 → 双击 `start-demo.bat` → 浏览器自动打开 | 36.6 MB |
| `release/cr-report-src.zip` | 要改代码的人 | Node ≥ 20.19 + pnpm ≥ 8.6，然后 `pnpm install` | 18.3 MB |

演示包里是：`dist/`（构建产物）+ `node/node.exe`（Windows 版 Node 运行时，打包时从 nodejs.org 下载并**用官方 SHASUMS256.txt 校验 sha256**）+ `server/serve.mjs`（自定位静态服务，端口被占自动顺延）+ `start-demo.bat` + `README.txt`（给对方看的说明）。包内路径全部用 ASCII 命名，避免 Windows 自带解压工具把中文文件名弄成乱码。

### 可移植性是怎么验的（不是"应该能跑"）

| 验证 | 做法 | 结果 |
| --- | --- | --- |
| **断网可用** | 用一个注入 `--host-resolver-rules="MAP * ~NOTFOUND, EXCLUDE localhost"` 的 Chrome 包装脚本跑 `pnpm e2e`（除本机外全部 DNS 黑洞） | **10/10 通过** |
| **零第三方外联** | 探针 `document.querySelectorAll('script[src]')` 过滤掉本机地址 | 返回 `[]`（原先会注入 `hm.baidu.com`，见下） |
| **交付包本身可用** | 用包内的 `server/serve.mjs`（从别的目录启动）跑 `pnpm e2e` | **10/10 通过**；端口占用时自动 4199 → 4200 |
| **源码包自足** | `git archive HEAD` 导出全新树 → `pnpm install` → `pnpm build:demo` → `pnpm dev` | 全部通过（依赖下载复用本机 store，**未验证**从零走公网拉 1.2G 依赖的那段） |
| Windows 运行时 | `file node/node.exe` | `PE32+ executable (console) x86-64, for MS Windows` |

> **诚实边界**：`start-demo.bat` 与 `node.exe` 本身**无法在 macOS 上实跑**（手上只有 Mac），上表验的是产物结构、服务脚本与 .bat 的逻辑；对方首次双击若报错，`README.txt` 里写了排查步骤（含 SmartScreen 与杀软误报两条）。

### 换电脑时真正会踩的坑（本轮已修）

1. **别直接拷 `node_modules/` 和 `.pnpm-store/`**（共 2.3 G）：pnpm 的 `node_modules/.modules.yaml` 里写死了本机绝对路径 `storeDir`，拷过去只会得到一个"看起来装好了其实坏了"的目录。源码包用 `git archive` 生成，天然不含这两样。
2. **百度统计原先默认开着**：`.env` 里 `VITE_APP_BAIDU_CODE` 有值，每次打开页面都会往 `hm.baidu.com` 发一次请求（实测注入成功）。给银行/保险客户演示时这既不合规、离线时也是一次必然失败的外联 —— 现已**留空关闭**，产物里 grep 不到 `baidu`。
3. **`pnpm-workspace.yaml` 里是没填完的占位符**（`set this to true or false`）：新机器 `pnpm install` 会报 `ERR_PNPM_IGNORED_BUILDS`，容易被当成"装坏了"。已按实测填成 `false`（这四个 postinstall 对本项目没有影响，全新树上装完可正常构建与启动）。
4. **自检脚本原先只认 macOS 的浏览器路径**：五个脚本里各写了一份 `resolveChrome`，到 Windows 上 `pnpm e2e:pages` 直接报"找不到可用的无头浏览器"。已合并为 `scripts/e2e/chrome.mjs`，覆盖 macOS / Windows / Linux 的 Chrome 与 Edge，仍可用 `CHROME_BIN` 覆盖。
5. **改 `.env` 会让 dev server 自动重启**：重启窗口内跑门禁会得到一条假失败（`Failed to fetch dynamically imported module: /src/layout/Layout.vue`）。隔几秒重跑即满分——**别照着这条去改代码**。
6. `scripts/e2e/crud.mjs` 原先把 `http://localhost:5173` 写死，现在也认 `APP_URL`，可以在静态产物或别的端口上跑。
